# SprintOS Latest Risk Register

| Risk | Category | Severity | Likelihood | Evidence | Impact | Current Mitigation | Gap | Recommended Fix | Priority |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Live provider instability | AI reliability | High | Medium | Older diagnostics/prototypes show timeouts and provider failures; current OpenAI status is ready but live acceptance was not rerun in this audit | Create App may fail or stop in report-only mode | Offline fallback, retry/repair, diagnostics, readiness status | No routine live acceptance signal | Add opt-in live acceptance baseline for canonical shapes and record redacted results | P0 |
| AI returns valid JSON but invalid app shape | App quality | High | Medium | Shape validators reject missing business/budget/flashcard surfaces; tests cover app-shape failures | User gets no AI app in report-only mode or fallback in template mode | Canonical shape contracts and validation details | Prompt/contract still depends on provider compliance | Keep shape repair path, run canonical live acceptance, tighten failing shape prompts only from evidence | P0 |
| Fallback hides real AI failure | Trust | High | Low | Template mode intentionally falls back; report-only was added to avoid false success | User may think AI generated an app when it did not | App state fallback banners, metadata, diagnostics | User copy can still be technical or missed | Keep fallback visible in main app state and translate reasons into plain categories | P0 |
| Report-only mode stops too often | UX/reliability | Medium | Medium | Current runtime has `report_only` enabled; this is right for AI-only testing but strict for daily use | User may get failure reports instead of a local prototype | Failure reports are sanitized and explicit | Mode intent may not be obvious before Create App | Clarify preflight and recommend template mode for normal local creation | P1 |
| Generated app passes structure but fails usefulness | App quality | High | Medium | Static checks prove surfaces and JS markers, not full semantic usefulness | A "valid" app can still feel weak or unhelpful | App-specific templates, shape validation, Test App | No broad behavioral/browser acceptance for generated apps | Add deterministic app-specific behavior checks and live acceptance review rubric | P0 |
| API key leakage | Security | Critical | Low | `.env` exists locally; many export/report paths exist | Secret exposure would break trust | Health scan, redaction, no key storage, package exclusions | Route sprawl increases future mistake risk | Keep central redaction/ZIP helpers and add assertions when any packaging route changes | P0 |
| Browser-side provider calls | Security | Critical | Low | Generated browser apps are explicitly forbidden from calling providers | Keys or external dependencies could leak into prototypes | Validation blocks provider markers, fetch, XHR, sendBeacon, external URLs | Obfuscated or novel network APIs could bypass simple checks | Expand generated-app safety checks when new app shapes are added | P1 |
| `.env` packaging regression | Security/local safety | Critical | Low | Workspace, package, backup, snapshot, and ZIP flows all copy files | `.env` could be included in exported artifacts | Tests and helpers exclude `.env`, `.env*`, `.git` | New artifact routes can forget exclusions | Require package-level secret/exclusion tests for every new file-copy flow | P0 |
| Stale process or wrong `.env` | Runtime | Medium | Medium | Server status is local and healthy now, but runtime behavior depends on current process env | User can inspect a server with old settings after editing `.env` | `/api/server_status`, Setup Doctor, launcher reuse checks | Restart guidance can be missed | Improve preflight/runtime copy only if users hit this repeatedly | P2 |
| Source/preview divergence | QA | Medium | Medium | Prototype, Deploy Pack, Build Pack, Workspace, and Release Pack can represent different snapshots | User may inspect one artifact and preview another | Latest-artifact hydration and reports | No simple checksum/manifest comparison in main lane | Add source/preview manifest compare only after reliability work | P2 |
| Overbuilding before app generation works | Strategy | High | High | Many advanced panels and artifact concepts already exist | Core user promise can be buried under infrastructure | AGENTS and docs say no overbuilding | Backlog still contains many follow-ups | Freeze broad feature surface; prioritize acceptance and quality | P0 |
| Monolith maintainability | Maintainability | High | High | `sprintos.py` is about 30,067 lines | Every change risks unrelated behavior | Some helpers in `sprintos_core/` | App generation, UI, routes, persistence still cross the monolith | Extract stable helpers only after app-generation reliability work | P2 |
| User confusion / decision fatigue | UX | Medium | High | UI/docs still expose Build Pack, Deploy Pack, Workspace, pipeline, Artifact History, AI Diagnostics | User may not know what to click after Create App | App Draft and Command Center are now prominent | Advanced vocabulary remains visible | Reduce main-lane vocabulary after reliability tasks | P1 |
| No local backup | Local safety | Medium | High | Setup Doctor score 92 with warning: no local backup exists; `local_backups` count is 0 | User can lose local SprintOS state | Setup Doctor recommends first backup | Recommendation can be ignored | Create first backup manually; keep compact warning until done | P1 |
| No Git commit history | Workflow safety | Medium | High | Git worktree exists but `git log` reports no commits on `main` | Hard to review, rollback, or split PR-sized changes | None beyond filesystem state | User/source changes are not protected by history | Add local initial commit or documented Git safety step before implementation work | P1 |
| App-name/prototype-type mismatch | UX polish | Low | Medium | Recent titles include app names paired with old prototype type labels such as calculator/landing page | Generated app can feel like an artifact, not a product | Concise app names exist in metadata | Display suffixes remain confusing | Clean labels after reliability and acceptance work | P3 |
